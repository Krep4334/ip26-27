# Спецификация требований

Версия 1.0

## 1. О приложении

«Учебный прокат» — локальный CLI для бронирования оборудования в вузе. Студент уже может найти устройство, забронировать его и вывести список своих броней. Планируется отмена и режим ответственного за выдачу с общим списком, выдачей и возвратом. Роли обозначают действия людей в учебном процессе. Приложение рассчитано на доверенную локальную среду, где доступ к файлу базы регулируется средствами ОС.

- **Студент** — пользователь с положительным целочисленным идентификатором.
- **Оборудование** — отдельный экземпляр с идентификатором и названием.
- **Бронь** — запись, связывающая студента с устройством. В текущей версии активная бронь имеет статус `reserved`. В модели будущей версии активны также выданные брони `issued`.

**UR-1.** Студенту нужно найти доступное оборудование и управлять собственными бронями (FR-1–FR-4).
**UR-2.** Ответственному нужно видеть общий список и отслеживать передачу оборудования (FR-5–FR-6).

## 2. Требования к функционалу

| № | Требование | Приоритет | Состояние | Признак выполнения |
|---|---|---|---|---|
| FR-1 | Студент может просматривать каталог оборудования и видеть доступность. | Обязательно | Есть | На новой базе каталог показывает `1 Проектор`, `2 Микрофон`, `3 Ноутбук`, все с `available: true`. После брони проектора его `available` становится `false`. |
| FR-2 | Студент может бронировать доступное оборудование. | Обязательно | Есть | Запрос к свободному устройству создаёт одну бронь. Повторный запрос к тому же устройству возвращает `equipment_unavailable` с кодом 4. |
| FR-3 | Студент может просматривать свои брони по идентификатору студента. | Обязательно | Есть | После бронирования команда показывает запись за указанным студентом. Для другого идентификатора список пуст. |
| FR-4 | Студент может отменять свою бронь до выдачи. | Обязательно | Нужно сделать | После отмены бронь остаётся в истории со статусом `cancelled`, а устройство доступно для новой брони. |
| FR-5 | Ответственный может просматривать список броней всех студентов. | Обязательно | Нужно сделать | Список показывает брони двух разных студентов с их идентификаторами и статусами. |
| FR-6 | Ответственный может фиксировать выдачу и возврат оборудования по брони. | Обязательно | Нужно сделать | Выдача меняет `reserved` на `issued`, возврат — `issued` на `returned`. В каталоге устройство освобождается только после возврата. |

### Ограничения

- **NFR-1.** Команды запускаются из чистого клона на Windows и Linux под Python 3.13.5 без сторонних пакетов. Проверка — выполнить сценарий из README на обеих ОС.
- **NFR-2.** Бронь сохраняется в SQLite после завершения процесса. Проверка — создать бронь и запустить `my-bookings` отдельным процессом с тем же `--db`.
- **NFR-3.** Одновременно допускается не более одной активной брони для одного устройства. Проверка — отправить два запроса на свободное устройство и получить одну запись и один отказ.

## 3. Пользовательские сценарии

### US-1 · FR-1 · Есть

Я как студент имею на входе новая база SQLite, выполняю `catalog` и получаю JSON-массив с идентификаторами, названиями и признаками доступности.

На новой базе у проектора `id: 1` и `available: true`. Если путь `--db` указывает в несуществующий каталог, CLI возвращает `database_error` с кодом 5 и каталог не выводится.

### US-2 · FR-2 · Есть

Я как студент имею на входе идентификатор студента и идентификатор устройства из каталога, выполняю `book --student 7 --equipment 1` и получаю идентификатор и статус `reserved`, доступность устройства меняется.

На новой базе студент 7 получает `{"id": 1, "student_id": 7, "equipment_id": 1, "status": "reserved"}`. Если студент 8 пытается забронировать уже занятый проектор № 1, он получает `{"error": "equipment_unavailable"}` с кодом 4. Новая бронь не создаётся.

### US-3 · FR-3 · Есть

Я как студент имею на входе идентификатор 7 и бронь № 1, выполняю `my-bookings --student 7` и получаю список броней студента 7.

Для студента 7 с бронью № 1 ответ — `[{"id": 1, "student_id": 7, "equipment_id": 1, "status": "reserved"}]`. Если обязательный параметр `--student` пропущен, CLI выводит `the following arguments are required: --student`, возвращает код 2 и не выводит список.

### US-4 · FR-4 · Нужно сделать

Я как студент имею на входе свой идентификатор и номер брони в статусе `reserved`, выбираю свою бронь и выполняю отмену и получаю статус `cancelled`, устройство освобождается.



### US-5 · FR-5 · Нужно сделать

Я как ответственный имею на входе локальный доступ к приложению и база с бронями, открываю общий список и вижу номера броней, студентов, устройства и статусы.



### US-6 · FR-6 · Нужно сделать

Я как ответственный имею на входе номер брони и физически передаваемое устройство, отмечаю выдачу, а при возврате отмечаю, что устройство принято и вижу статусы `issued` и `returned` по порядку, устройство снова доступно.
